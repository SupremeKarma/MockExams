Q: What is the "incremental iterative approach" to software development?
A) Building the entire system in one single pass with no revisiting
B) Developing the software in small increments, each revisited and refined through repeated iterations, delivering usable versions progressively
C) A purely theoretical model never used in real projects
D) A model that forbids any changes once coding starts
ANSWER: B
EXPLAIN: The incremental iterative approach breaks development into smaller increments, each going through iterative refinement (design, build, test), delivering a working version of the system progressively rather than all at once — reducing risk and allowing earlier feedback.

Q: What does the RAD (Rapid Application Development) model emphasize?
A) Long, sequential phases with no user involvement until final delivery
B) Fast development and delivery through component-based construction, heavy user involvement, and short, time-boxed development cycles
C) Zero prototyping or user feedback
D) Only applicable to hardware-based embedded systems
ANSWER: B
EXPLAIN: RAD emphasizes rapid, iterative development using reusable components and heavy user involvement, aiming to deliver a working system quickly through short, time-boxed cycles — trading some scalability/flexibility for development speed.
DIFFICULTY: medium
MARKS: 12

Q: What is the key difference between functional and non-functional requirements in software development?
A) Functional requirements describe what the system should do; non-functional requirements describe quality attributes like performance, security, and usability
B) They are the same concept with different names
C) Non-functional requirements only apply to hardware systems
D) Functional requirements are always optional
ANSWER: A
EXPLAIN: Functional requirements specify what the system must do (features, behaviors, functions), while non-functional requirements specify how well the system performs — qualities like performance, reliability, security, usability, and scalability — that constrain the solution.
DIFFICULTY: medium
MARKS: 12

Q: Why is software testing done?
A) Only to satisfy a contractual formality
B) To identify defects and verify that the software meets its specified requirements and behaves correctly, improving quality before release
C) Testing is never necessary if the code compiles
D) Only to test the hardware the software runs on
ANSWER: B
EXPLAIN: Testing is performed to systematically find defects and verify that software meets its functional and non-functional requirements, ensuring quality and reliability are established before deployment rather than discovered by end users.

Q: What is Software Engineering as a "Layered Technology"?
A) A model where software engineering rests on layers: a quality focus, process, methods, and tools, each building upon the one below
B) A description referring only to network protocol layers
C) A term unrelated to software development methodology
D) A synonym for object-oriented programming
ANSWER: A
EXPLAIN: Pressman's layered technology view describes software engineering as founded on a quality focus, with process defining the framework, methods providing technical how-to, and tools providing automated support — each layer building on and supporting the one beneath it.

Q: What does the COCOMO (Constructive Cost Model) primarily estimate?
A) Only the number of developers on a team
B) Software development effort, time, and cost based on estimated lines of code and project complexity
C) The exact bugs a project will contain
D) Only hardware requirements for deployment
ANSWER: B
EXPLAIN: COCOMO is an algorithmic cost estimation model that uses estimated lines of code (KLOC) along with complexity/mode factors to predict development effort (person-months), development time, and required team size for a software project.

Q: What is Object-Oriented Software Engineering (OOSE) primarily concerned with?
A) Only writing code without any design phase
B) Applying object-oriented concepts (classes, objects, inheritance) throughout the entire software development lifecycle, including analysis and design
C) A methodology exclusively for embedded systems
D) A synonym for procedural programming
ANSWER: B
EXPLAIN: OOSE is a methodology that applies object-oriented principles — such as classes, objects, encapsulation, and inheritance — not just to coding, but throughout the full software development lifecycle including requirements analysis, design (e.g. via class diagrams), and implementation.
DIFFICULTY: medium
