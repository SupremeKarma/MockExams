Q: What is the primary purpose of the System Development Life Cycle (SDLC)?
A) To provide a structured, phased framework (e.g. planning, analysis, design, implementation, maintenance) for developing and delivering an information system
B) To eliminate the need for any requirements gathering
C) To replace the need for testing entirely
D) To only describe how to write source code
ANSWER: A
EXPLAIN: The SDLC provides a structured sequence of phases — typically including planning, analysis, design, implementation, and maintenance — that guides a systems project from initial concept through delivery and ongoing support, ensuring each stage's output feeds correctly into the next.

Q: What does a "context diagram" represent in system analysis?
A) The detailed internal database schema of a system
B) The highest-level Data Flow Diagram (DFD), showing the entire system as a single process along with its external entities and the data flows between them
C) A diagram showing only the source code structure
D) A timeline of project milestones
ANSWER: B
EXPLAIN: A context diagram is the top-level DFD (DFD level 0) that represents the whole system as one process, showing only its boundary — the external entities it interacts with and the major data flows in and out — without any internal process detail.

Q: What is the significance of the Entity-Relationship (E-R) model in system design?
A) It has no practical use in database design
B) It provides a conceptual, graphical way to model the data requirements of a system — entities, their attributes, and the relationships between them — before implementing the physical database
C) It only applies to programming logic, not data
D) It replaces the need for any database at all
ANSWER: B
EXPLAIN: The E-R model lets analysts represent real-world data entities (e.g. Employee, Department, Project), their attributes, and the relationships between them (e.g. one-to-many, many-to-many) in a conceptual diagram, which is later translated into a physical relational database schema.

Q: What is the key difference between a decision table and a decision tree in system analysis?
A) A decision table represents complex conditional logic in a structured tabular grid of conditions and actions; a decision tree represents the same logic as a branching, hierarchical diagram
B) They represent completely unrelated concepts
C) A decision tree can only have one branch
D) Decision tables cannot represent multiple conditions
ANSWER: A
EXPLAIN: Both tools represent conditional business logic, but a decision table organizes conditions and corresponding actions into rows/columns of a grid (useful for many combined conditions), while a decision tree visually branches out from conditions to outcomes — often more intuitive for sequential decision logic.

Q: Why is normalization (e.g. converting a table to 1NF, then 2NF) required in database design?
A) To intentionally increase data redundancy
B) To organize data to reduce redundancy and avoid update, insertion, and deletion anomalies by ensuring each table has a clear structural purpose
C) To make queries slower
D) Normalization is purely optional and has no practical benefit
ANSWER: B
EXPLAIN: Normalization systematically restructures tables to eliminate repeating groups (1NF) and remove partial dependencies on a composite key (2NF), reducing data redundancy and preventing anomalies that occur when the same fact is stored in multiple places inconsistently.

Q: What is a "use-case diagram" primarily used to represent in system analysis?
A) The physical network topology of a system
B) The functional interactions between external actors (users or systems) and the system's use cases (specific functions/goals they can perform)
C) Only the internal class structure of the code

EXPLAIN: A use-case diagram shows the functional scope of a system by depicting actors (users or external systems) and the use cases (discrete tasks or goals) they can perform with the system, along with relationships like include/extend between use cases.
