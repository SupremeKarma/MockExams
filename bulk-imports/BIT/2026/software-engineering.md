Q: What best describes the "Waterfall model" of software development?
A) An iterative, flexible model with overlapping phases
B) A linear sequential model where each phase (requirements, design, implementation, testing, maintenance) must complete before the next begins
C) A model with no defined phases at all
D) A model used only for hardware design
ANSWER: B
EXPLAIN: The Waterfall model is a linear-sequential approach where development flows steadily downward through distinct phases — requirements, design, implementation, verification, and maintenance — with each phase expected to complete before the next starts.

Q: What is a key disadvantage of the Waterfall model?
A) It is too flexible to changing requirements
B) It is difficult and costly to go back and make changes once a phase is completed, since requirements aren't revisited until late
C) It has no defined phases
D) It cannot be used for any real project
ANSWER: B
EXPLAIN: Because the Waterfall model expects each phase to be fully completed before moving to the next, discovering a problem or a changed requirement late in the process is costly and difficult to accommodate, since going back to an earlier phase disrupts the linear flow.

A) All processing happens on a single standalone machine
B) A server provides resources/services that multiple client machines request and consume over a network
C) There is no network communication involved

EXPLAIN: In a client-server architecture, one or more server components provide services or resources (like data or computation), while client components request and consume those services over a network, dividing responsibilities between the two roles.

Q: What does CPM (Critical Path Method) help project managers determine?
A) The exact lines of code needed for a project
B) The longest sequence of dependent tasks that determines the minimum possible project duration
C) The color scheme of the software's UI
D) The number of developers needed regardless of task dependencies
ANSWER: B
EXPLAIN: CPM identifies the critical path — the longest chain of dependent tasks through the project network — which determines the shortest possible time to complete the project; delays on this path directly delay the whole project.

Q: What is the key difference between verification and validation in software testing?
A) Verification asks "are we building the product right?" (matches specification); validation asks "are we building the right product?" (matches user needs)
B) They are the exact same activity with different names
C) Verification happens only after deployment
D) Validation only applies to hardware systems
ANSWER: A
EXPLAIN: Verification checks whether the software correctly implements its specified requirements ("building the product right"), while validation checks whether the software actually satisfies the user's real needs and intended use ("building the right product").

Q: What does "cyclomatic complexity" measure in software?
A) The number of lines of code in a file
B) The number of independent linearly-independent paths through a program's source code, indicating its structural/logical complexity
C) The number of developers who worked on the code
D) The runtime memory usage of the program
ANSWER: B
EXPLAIN: Cyclomatic complexity is a software metric that counts the number of linearly independent paths through a program's control flow graph, giving an indication of the code's structural complexity and how thoroughly it needs to be tested.
